# AstrWeChat 1.3.2

## 会话选择器修复

- 消息过滤扫描不再仅保留 `@chatroom` 群聊，私聊也可直接勾选加入白名单；列表、刷新和搜索统一为会话入口，增加群聊/私聊类型标识。
- 扫描后补全联系人备注和昵称；失败或超时仍保留真实会话 ID。移除将消息摘要当成名称的回退，避免列表显示为 `[消息]`。
- 修复消息推送时原始会话 ID 抢占已解析昵称的问题，使回复路由使用可用的联系人显示名称。
- 保留旧搜索发送模式的过滤范围，不扩大其原有私聊限制；独立窗口模式继续对私聊和群聊执行白名单校验。

## 独立窗口发送

- 基于当前 1.3.1 工作区源码创建独立版本目录，保留其未提交功能修改，不修改原版本。
- Bridge → 基础配置 → 行为设置新增“独立窗口发送”，默认关闭。
- 仅消息过滤为白名单时可开启；开启后禁止改成黑名单。配置保存、Bridge 启动和 Python 配置更新均校验此约束。
- 开启时持续提醒：请手动将白名单中的每个会话打开为独立聊天窗口，保持窗口存在，可最小化。
- 文字、图片、文件发送均按窗口标题精确匹配，再激活对应 HWND；不存在或匹配多个窗口时拒绝发送，不回退搜索。
- 粘贴与回车前重新检查目标标题、进程、前台窗口及搜索界面状态；焦点被抢走时停止。
- 此模式对群聊、私聊以及本地指令回复统一限制白名单；空白名单不发送。关闭后保留原来的搜索发送与私聊行为。
- 切换模式后保存会重启正在运行的 Bridge，避免旧队列混用发送模式。

# 继承版本：AstrWeChat 1.3.1

## 新增本地指令与管理员（源码已实现，待微信实机验收）

- 新增 `#AW` 菜单，以及 `#UID`、`#STATUS`、`#STOP`、`#START`、`#AC` 和 `#AC <回溯码>`，本地处理且不转发至机器人服务端。
- 侧边栏新增独立“AW配置”页面，提供稳定 UID 管理员、备注和回溯附件缓存限制；保存后热更新。
- 当前群回显最近 10 条消息，回溯码位于附件消息同一行右侧；使用精确消息匹配、原群鉴权、缓存期限和容量控制。
- 会话暂停清理未转发缓冲，恢复不补发旧消息；异步媒体和计时器增加代次隔离。
- 修复微信当前停留在其他会话时，联系人搜索尚未完成就把 #AW 菜单继续粘贴进搜索框的问题；现在直接复用原有 Bridge 普通消息发送流程，仅延长搜索结果加载和进入会话后的等待时间，再粘贴实际消息。
- 新功能验证后 Bridge 回归共 64 项 Node 测试、40 项 Python 测试通过，两组类型检查和模拟设置页交互通过。
- 此次未重新打包安装包，也未替代真实微信端到端验收。使用说明见 `docs/local-commands.md`。

## Windows 程序命名

- Windows x64 主程序统一为 `AstrWeChat.exe`，应用名称为 AstrWeChat。
- 构建时对输出目录的 WCDB DLL 做限定哈希的宿主名称兼容适配，保留仓库中的原始 DLL。
- 保留原有用户数据目录和配置，不执行数据迁移。
- 此名称适配仅支持 Windows x64；Windows ARM64 构建暂时阻止，避免生成无法连接数据库的程序。

## Bridge 启动修复

- 修复数据库已连接时，Bridge 连接检查仍排在原生慢查询之后导致启动超时的问题。
- 连接状态由 Worker 的真实句柄状态确认；关闭、切号、错误或退出时及时失效。
- 同账号预热复用已确认的连接，避免重复排队打开数据库。
- 增加后台慢请求提示，区分“已有连接”和“查询仍在等待”。
- 修复 Worker 正常退出后请求未结束、旧 Worker 回包影响新连接及消息发送异常残留请求的问题。
