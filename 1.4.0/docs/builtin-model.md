# 1.4.0 内置模型模式

Bridge 基础配置选择「内置模型」后，填写 API 格式、基础地址、Key、模型名和系统提示词，保存并启动。AstrBot、KouriChat、内置模型三选一；切换会先停止旧 Bridge。模型调用失败默认只写日志；可手动开启向当前会话发送错误码，不会自动切换服务端。

- Chat Completions：兼容 `/v1/chat/completions` 的服务端，默认基础地址 `https://api.openai.com/v1`。
- Responses：支持 `/v1/responses` 的服务端，须明确选择，不能假定所有 Chat Completions 兼容服务商也支持 Responses。
- Anthropic Messages：基础地址默认 `https://api.anthropic.com`；第三方服务须实现 Anthropic 的 Messages 协议。

模型上下文只在 Bridge 进程内存中保留，不跨重启持久化。各会话独立，至多保留最近 40 个请求消息；群聊前置消息逐条作为 user 消息传入，发言人附在各条内容前，模型成功发送后才记 assistant 回复。群聊触发仍沿用 @、批量、主动回复概率和消息过滤规则。本地指令仍优先在 Bridge 内处理。媒体只发送文本描述，不上传文件或图片；内置模式不支持 AstrBot/KouriChat 的插件及斜杠命令功能，斜杠文本会作为普通用户请求送给模型。

群聊正文在写入模型上下文前移除「机器人昵称」中配置的 @昵称：例如 `@小冰 hi` 传给模型的正文为 `hi`，兼容全角 `＠` 和微信的特殊空格。当前消息及后续历史都使用清理后的正文，发言人等元数据仍保留，其他成员的 @ 不移除。该清理不修改原始微信事件，不影响 @触发判断，也不修改私聊正文。更新后重启 Bridge 生效。


## 查看错误码与启用失败通知

在「Bridge → 基础配置 → 内置模型」中勾选「发送错误码到当前会话（模型调用失败时）」并保存。开关默认关闭，保存变更会重启运行中的内置模型 Bridge；非内置模型模式不受影响。

开启后，模型请求失败或返回空回复时，向本次请求的原会话发送固定格式通知，例如：

```text
模型调用失败：[E_MODEL_AUTH] 模型鉴权失败（HTTP 401）。请检查 API Key 是否正确、有效，以及是否属于当前服务商。
```

通知仅包含稳定错误码、中文原因、可用的 HTTP 状态码和排查建议，不包含服务商原始错误正文、响应头、密钥、请求文本或本机路径。日志额外记录异常类型，便于诊断；初始化错误仍保留脱敏后的依赖名、环境及堆栈。

- 同一会话 60 秒内最多尝试一次通知，避免故障刷屏；通知失败也不自动重试。
- 通知同样遵守全局/会话暂停、停止、白名单、运行代际以及 UIA 发送前的权限复查，不会回退搜索其他会话。
- 通知不写入模型的 assistant 历史；本地发送回显会被过滤，避免再次触发模型。
- 模型已成功生成但微信发送失败时，只记录 `E_WECHAT_SEND`，不会再发送“模型调用失败”或自动重发。
- 启动失败、请求队列已满及内部处理异常只写日志；没有启动的模型或已跳过的任务不会向会话发送通知。
- HTTP 429 可能是限流，也可能是配额不足；404 可能是模型名或接口路径错误，需结合服务商后台检查，不依据敏感的原始响应猜测。

| 错误码 | 含义 | 排查建议 |
| --- | --- | --- |
| `E_MODEL_AUTH` | 模型鉴权失败 | 请检查 API Key 是否正确、有效，以及是否属于当前服务商 |
| `E_MODEL_PERMISSION` | 模型访问被拒绝 | 请检查账号、模型权限及服务商访问限制 |
| `E_MODEL_NOT_FOUND` | 模型或接口不存在 | 请检查模型名称、API 基础地址及接口格式 |
| `E_MODEL_QUOTA` | 模型服务要求付费或额度不足 | 请检查服务商余额、套餐及额度 |
| `E_MODEL_RATE_LIMIT` | 模型服务限流或配额不足 | 请稍后重试，并检查服务商限流与配额 |
| `E_MODEL_TIMEOUT` | 模型请求超时 | 请检查网络，或适当增加请求超时后重试 |
| `E_MODEL_NETWORK` | 无法连接模型服务 | 请检查网络、代理、DNS、证书和 API 基础地址 |
| `E_MODEL_REQUEST` | 模型服务拒绝请求参数 | 请检查接口格式、模型能力、上下文和图片参数 |
| `E_MODEL_CONTEXT` | 当前消息或提示词超过本地输入预算 | 缩短内容或调整上下文、最大输出设置 |
| `E_MODEL_TOO_LARGE` | 模型请求内容过大 | 请减少上下文或关联图片后重试 |
| `E_MODEL_SERVER` | 模型服务端异常 | 请稍后重试，或检查服务商运行状态 |
| `E_MODEL_HTTP` | 模型接口返回异常状态 | 请检查 API 基础地址、接口格式及服务商状态 |
| `E_MODEL_RESPONSE` | 模型响应格式异常 | 请检查所选接口格式与服务商是否兼容 |
| `E_MODEL_FILTERED` | 模型服务拒绝生成此内容 | 请调整提问内容后重试 |
| `E_MODEL_EMPTY` | 模型返回了空回复 | 请调整提问，或检查模型与接口格式 |
| `E_MODEL_DEPENDENCY` | 模型依赖缺失或不兼容 | 请安装完整版本，并确认 Python 版本与随包依赖匹配 |
| `E_MODEL_CONFIG` | 模型配置无效 | 请检查模型名称、API Key、基础地址和超时设置 |
| `E_MODEL_UNKNOWN` | 模型调用失败，原因未识别 | 请联系管理员查看 Bridge 日志中的异常类型 |
| `E_MODEL_QUEUE_FULL` | 模型请求队列已满，本次回复已跳过 | 请等待已排队请求处理完成后重试 |
| `E_WECHAT_SEND` | 模型已生成回复，但微信发送失败或被中止 | 请检查微信窗口、发送权限及独立聊天窗口；不会自动重发 |
| `E_ERROR_NOTIFY_SEND` | 错误码通知发送失败或被中止 | 请检查微信窗口及发送权限；不会自动重发 |
| `E_BRIDGE_PROCESS` | Bridge 处理消息失败 | 请联系管理员查看 Bridge 日志中的异常类型 |
| `E_BRIDGE_INIT` | 非内置模型 Bridge 初始化失败 | 查看脱敏后的异常堆栈和运行环境 |


## 获取上游模型与长度适配

1. 在内置模型卡片填写接口格式、API 基础地址和 API Key，点击“获取上游模型”。此操作只查询列表，不发送聊天内容、不保存草稿、不切换当前后端。
2. 在返回列表中选择模型；仍可手动输入模型 ID。当前已填写的模型在列表中存在时，会同步其能力信息。
3. 卡片显示上游提供的上下文窗口、输入上限、输出上限和识图能力。上下文填 `0` 表示自动；最大输出默认 `2048`。保存后按实际参数重启内置模型 Bridge。

模型列表只访问用户填写的服务商，不从第三方模型目录猜测同名模型能力。Chat Completions / Responses 查询基础地址下的 `/models`；Anthropic 查询 `/v1/models`，已有 `/v1` 不重复追加。使用对应鉴权头，禁止重定向转发密钥，20 秒总超时，最多 10 页、2000 个模型、8 MiB 响应。HTTP 状态、网络、超时、响应格式各有 `E_MODELS_*` 提示，不暴露响应正文或密钥。

- 兼容 `context_length`、`context_window`、`max_context_length`、`max_input_tokens`、`max_input_length`、`max_output_tokens`、`max_completion_tokens`、`max_tokens`、`top_provider`、`limits` 等常见元数据；识图能力读取输入模态、`supports_vision` 或 `capabilities.image_input.supported`。
- 上游未提供的字段显示“未提供”。自动上下文优先使用上下文窗口，其次输入上限；都没有时使用本地 `32768` 预算，不宣称这是模型真实上限。可按服务商说明手动调整。
- 手动上下文不能突破已知上游窗口；实际最大输出取用户设置、已知输出上限及上下文一半中的最小值。随后预留安全余量，并遵守单独的输入上限。
- 未知 tokenizer 使用 UTF-8 字节保守估算文本，单张图片预留 4096 token 估算值；不是服务商精确计费值。优先裁剪旧历史，保留当前触发消息与合并消息，若仍超限报 `E_MODEL_CONTEXT`，不静默删掉用户当前问题。
- 本地保留最近 64 个会话，每会话最多 120 条、256000 字符；单次最多 40 条历史。单条当前消息超过本地 256000 字符限制会明确报错。清空会话时，发送中的旧回复不会恢复已清空历史。
- 元数据绑定基础地址、接口格式及精确模型 ID；修改地址、Key、接口或手动模型名后清空旧信息，迟到的旧列表响应不会覆盖新设置。上游明确不支持图片时关闭关联图片输入。

接口字段依据核对于 2026-09-27，参考 `https://developers.openai.com/api/reference/resources/models` 与 `https://platform.claude.com/docs/en/api/models/list`：OpenAI List models API 的标准响应不保证提供上下文长度；Anthropic Models API 包含可为空的 `max_input_tokens`、`max_tokens` 与能力信息。实现只使用真实返回值，测试使用本地桩服务，不代表实际服务商均提供上述扩展字段。

## 分段回复

在内置模型卡片开启“分段回复”，保存后生效。默认关闭，不改变已有发送行为。

| 设置 | 默认值与行为 |
| --- | --- |
| 仅对 LLM 结果分段 | 默认开启。关闭后也处理内置模型错误通知；不改变 AW 本地指令、AstrBot/KouriChat 或文件发送 |
| 间隔方法 | `random`，每段间随机等待；可选 `log`，按上一段字符数计算 `log_base(字数)` |
| 随机间隔时间 | `1.5,3.5` 秒，允许 0–60 秒，最小值不得大于最大值 |
| 对数底数 | `2`，大于 1、不超过 100，等待最长 60 秒 |
| 分段回复字数阈值 | `150`，仅字数严格小于阈值才分段；达到或超过时原文整条发送，不执行内容过滤 |
| 分段模式 | 正则表达式；也可选择按换行分段 |
| 分段正则表达式 | 默认按中文/英文句末标点、换行、波浪号与省略号分段，保留标点及未匹配内容 |
| 内容过滤正则表达式 | 默认为空；例如 `[。？！]` 移除匹配标点，空段不会发送 |

首段立即发送，后续段依序等待；每段和发送前均检查暂停、停止、会话权限及代次。失败或取消后不重发，模型历史只记入已经确认发送的内容；全部过滤为空时跳过发送。仅关闭“仅对 LLM”时，错误通知可拆成多段，但仍按整次通知限频，每段登记回显抑制，不进入模型历史。

正则使用随模型依赖附带的 Python `regex`，最多 512 字符；启动时校验语法。运行时每次匹配/过滤最多 50ms，禁止空匹配，最多发送 20 段，多余内容并入末段。运行时失败或超时记录 `E_REPLY_SEGMENT`，按原文整条发送；过滤后为空记录 `E_REPLY_FILTERED`。

## Python 运行环境与打包

Windows x64 安装包同时提供 CPython 3.10 和 3.12 的模型依赖；仍需已有 Python 解释器和原有 UIA 依赖。构建时附带的是模型 SDK，不是完整 Python 解释器，也不会向 AstrBot 的 Python 环境安装或升级依赖。

| 解释器 | 模型依赖目录 | 加载规则 |
| --- | --- | --- |
| CPython 3.10 x64 | `bridge/vendor` | 保持原有安装包布局 |
| CPython 3.12 x64 | `bridge/vendor/cp312-win_amd64` | 加载独立的 cp312 原生模块及其依赖 |
| 其他版本或架构 | 解释器自己的环境 | 不加载不兼容的随包原生模块 |

在版本目录执行 `npm run build`。构建脚本使用 `uv` 按两个 Python 版本分别安装 `bridge/model-requirements.txt` 中固定的 SDK，检查关键传递依赖及原生模块，再由安装包校验阻止依赖缺失的包发布。首次构建需要网络及已安装的 uv，也可设置 `ASTRWECHAT_UV` 指定 uv 可执行文件。完整的已有依赖目录不会重复下载；新增 3.12 目录不改变原有 3.10 依赖。

### 遇到 `No module named 'pydantic_ai'`

先看日志中的 Python 版本、解释器路径和内置依赖目录。旧包只带 cp310 依赖，使用 AstrBot 的 Python 3.12 时会跳过这些不兼容的文件。更新到带 cp312 依赖的修复安装包后，3.12 启动日志应显示 `vendor/cp312-win_amd64`。不要将 cp310 的 `.pyd` 强行复制给 3.12，也不必修改 AstrBot 的 site-packages。

若对应依赖目录缺失，应重新安装完整包；其他 Python 版本需在专用 Bridge 环境安装 `bridge/requirements.txt`，可用 `WEFLOW_BRIDGE_PYTHON` 指定解释器。开发模式沿用 `start.bat`。

本次回归使用 Python 3.10 和独立 Python 3.12.12，3.12 测试通过 `-S` 禁用 site-packages，仅使用随包模型依赖，并以本机 HTTP 模拟服务验证三种协议。未连接真实微信或真实模型端点做端到端验收。
