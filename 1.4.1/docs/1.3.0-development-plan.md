# AstrWeChat 1.3.0 开发范围

确认日期：2026-09-11。当前阶段：连接分组与互斥切换已实现，微信端到端验收及协议完善待继续。

连接使用与已验证范围见 `connection-profiles.md`。

## 已确认需求

1. 产品名为 AstrWeChat，沿用当前品牌，不因工作区目录或兼容性可执行文件名改变。
2. 在现有 Bridge 页面提供 AstrBot、KouriChat 两个独立连接配置分组。
3. 两组分别保存 WebSocket 地址和 Token，切换后不能相互覆盖。
4. 同一时间仅连接一个服务端；未启用组只保留配置，不启动连接或推送微信消息。
5. 复用现有消息读取、过滤、数字 ID 映射和微信发送能力，不再增加独立微信网关。

## 实施范围与后续事项

### 配置与界面

- 增加当前启用的服务端类型，并迁移旧配置；未配置新字段时默认沿用 AstrBot。
- AstrBot 和 KouriChat 分组分别保存配置，清楚区分已选中、未启用、连接中、已连接及错误状态。
- 既有 `astrbot_ob_url`、`astrbot_ob_token` 等配置需要兼容迁移，不丢失用户数据。
- 运行状态、工作流和日志文案显示真实服务端名称，不继续把 KouriChat 连接显示成 AstrBot。

### 互斥切换

- 校验目标配置后停止旧连接及其重连任务，再建立新连接；不能同时保留两个活动客户端。
- 明确处理旧连接的在途请求和待发送队列，避免旧回复被错误归属到新服务端或重复发送。
- 保存和切换行为需要明确；普通编辑未启用组配置不应干扰当前连接。
- 保持微信侧过滤规则及会话路由一致，避免切换后向错误联系人发送消息。

### KouriChat 适配

- 使用通用 `kourichat.adapter.onebot` 的反向 WebSocket 服务端，不使用 `adapter.openclaw` 微信网关。
- 同机联调地址可使用 `ws://127.0.0.1:6700`，通过相同的 Bearer Token 鉴权。
- 补齐消息事件 ID、消息子类型，以及可追踪的发送结果。
- 未实现的 API 动作应返回明确错误；不要将未执行或仅排队的动作统一报告为发送成功。
- KouriChat 当前 echo 处理存在同一 WS 读取循环等待回执的问题；最小联调先禁用 echo，后续单独修复。不得将此问题误判为 AstrWeChat 鉴权或连接失败。
- 图片段传输与模型图片理解分别验收；后者需要 KouriChat 会话层支持，不属于单纯切换连接配置即可实现的能力。

## 验收项

- [x] 旧版本 AstrBot 配置能迁移，地址和 Token 不丢失。
- [x] 两组配置独立保存，重新加载配置恢复启用组；页面刷新已验证。
- [x] 生命周期测试验证互斥进程、旧退出事件隔离和无效重连代次不复活。
- [ ] 切换与断线期间不串回执、不重复发送、不发错会话。
- [x] 无效目标配置有明确提示，不破坏当前可用配置。
- [ ] AstrBot 原有私聊、群聊、图片与发送队列行为通过回归。
- [ ] KouriChat 私聊和群聊文本完成真实微信端到端联调。
- [x] 当前服务端的鉴权失败、重连和退出显示明确状态，本地 WS 测试通过。

## 本次初始化边界

`1.3.0` 从当前 `1.2.0` 可版本管理的源码及资源复制，包括尚未提交的源码修改；不复制本机配置、凭据、运行数据、依赖目录或安装包。新版本继承既有启动与构建脚本。现已实现连接分组与互斥切换，尚未完成真实微信端到端联调，也没有生成或发布安装包。
