# AstrWeChat 1.3.0：AstrBot / KouriChat 连接

当前为开发版，尚未发布安装包。两种连接共用现有微信消息读取和发送能力，不同时运行。

## 使用

1. 在「微信连接」页面自动检测数据库和微信 ID，确认后连接。Bridge 直接沿用成功连接后保存的微信 ID，无需重复填写微信 API 地址、Access Token 或 Bot 微信 ID。
2. 打开 Bridge 的“基础配置”，在“机器人连接”中分别填写 AstrBot、KouriChat 的地址和 Token。
3. 勾选本次使用的服务端，再点击“保存配置”。仅勾选不会立即切换。
4. Bridge 已运行时，按钮会明确显示“保存并切换至 …”或“保存并重新连接”。程序先等待旧进程退出，再启动新连接。
5. Bridge 未运行时，保存只记住选择；点击启动才会连接。存在未保存修改时，“保存并启动”会先验证和保存配置。

未启用组也能编辑并保存，不会中断当前连接。Token 使用密码输入框；旧 AstrBot 地址、Token 与会话权限配置继续兼容。

## 微信推送自动关联

自 2026-09-15 的开发版修改起，桌面启动的 Bridge 自动使用本程序的微信连接：

- 微信身份直接读取「微信连接」页面成功连接后保存的微信 ID；自动检测填入的 ID 同样适用。Bridge 不再显示账号卡片，也不维护第二份身份。
- 点击启动 Bridge 时，先检查数据库连接，再自动启动所需 HTTP 服务和主动推送。未连接数据库时给出明确提示，不启动 Python Bridge。
- 已配置 API Token 时沿用；未配置时自动生成随机 Token。使用实际运行的监听地址和端口，通配监听地址转换为可连接地址。
- 旧 Bridge 配置里的微信来源地址、推送 Token、Bot 微信 ID 在保存或启动时由主程序覆盖；机器人服务端两组地址、Token 及消息过滤规则不变。
- 保存机器人配置本身不会开启 API、推送或机器人连接。仍需显式点击启动；本功能不自动替用户启动 AstrBot / KouriChat 收发。
- 重新打开或断开微信数据库前，先停止正在运行的 Bridge，避免旧身份继续发送；成功连接后按提示重新启动 Bridge，无需重填推送信息。
- 手动修改本地 API Token 时会安全重启活动 Bridge，使凭据保持一致；API 重新启动后也会同步实际地址。

此次是**自动配置**，底层仍使用现有 HTTP / SSE，图片等媒体仍走现有 API，不代表已实现纯内部管道传输。API 服务的导航入口和页面已移除，旧 `/api` 页面地址自动跳转到微信连接页；后台 HTTP / SSE 及媒体接口保留，由 Bridge 启动流程自动管理。

### 启动失败时

- “请先连接微信数据库”：先完成微信连接，再启动 Bridge。
- “自动启动微信推送服务失败”：检查 API 端口占用和监听地址；不会误报 Python Bridge 启动成功。
- “旧 Bridge 尚未退出”：先停止旧进程，确认退出后再切换微信；不并行运行新旧身份。

## KouriChat

同机默认地址：`ws://127.0.0.1:6700`。

在 KouriChat 已生成的 `kourichat.toml` 中修改对应段，不要重复追加相同适配器：

```toml
[[adapters]]
module = "kourichat.adapter.onebot"
[adapters.config]
mode = "reverse"
ws_host = "127.0.0.1"
ws_port = 6700
token = "双方相同的令牌"
```

- 关闭 `kourichat.adapter.openclaw`，此路径不需要独立微信网关或扫码。
- 首次联调关闭 `kourichat.logic.echo`，因为当前克隆版本的同步回显会阻塞自身 WS 回执读取；普通会话回复使用后台任务，不依赖 echo。
- 异机部署需要按实际地址配置监听和连接，并自行保护网络访问；示例默认限制本机访问。
- 两端 Token 必须一致；KouriChat 的 4001 关闭与服务端 HTTP 401/403 会显示鉴权失败。

## 切换与失败语义

- 配置保存、启动、停止由同一操作队列串行执行。连续点击或快速切换不会并行启动两个 Bridge。
- 目标地址无效时，不修改已保存配置，不停止当前连接。
- 旧进程未确认退出时，取消切换，保留旧配置；发送终止信号不等于已经退出。
- 更改当前机器人连接的地址或 Token 会重启 Bridge；编辑未启用组不会重启。微信身份与本地 API 参数由桌面程序管理，不再手动维护两份。
- 切换会丢弃旧进程尚未发送的回复，不会转交新服务端。已经发出的消息无法撤回。
- 新配置保存成功但新进程启动失败时，界面明确提示“配置已保存，但启动失败”，可修正后重试。
- 日志、状态和 Work 面板显示实际服务端；断线会自动重试。地址查询参数中的常见 Token 及已配置 Token 不写入连接日志明文。

## 配置字段

```json
{
  "bot_backend": "astrbot",
  "astrbot_ob_url": "ws://127.0.0.1:11229/ws",
  "astrbot_ob_token": "",
  "kourichat_ob_url": "ws://127.0.0.1:6700",
  "kourichat_ob_token": ""
}
```

未包含 `bot_backend` 的旧配置默认使用 AstrBot。两个服务端共用机器人微信身份、消息过滤与发送设置。

## 检查

在 `1.3.0` 目录运行：

```powershell
npm run typecheck
npm run typecheck:bridge
npm run test:bridge
npm run test:packaging
```

`test:bridge` 包含微信推送自动配置、空 Token 生成、已有凭据沿用、实际监听地址、断开数据库及端口失败保护、托管字段覆盖和凭据轮换测试，以及配置迁移、互斥切换、失败保护、输出分帧测试，以及本地真实 WebSocket 连接、鉴权、收发回执和重连测试。测试使用合成数据，不读取微信数据库，也不调用 UI Automation。

本轮另外对本地 KouriChat 的原始 OneBot 适配器完成了带 Token 的反向 WS、私聊/群聊事件、回复回执与 AstrWeChat 目标路由联调。前端连接分组在模拟桌面接口的本地页面中检查了布局、保存切换、错误提示及刷新后的配置恢复。
