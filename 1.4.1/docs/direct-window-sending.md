# 独立窗口发送

此功能从 1.3.2 开始提供，默认关闭。它省略联系人搜索，但仍会把目标微信窗口置前，不是后台静默发送。

## 开启步骤

1. 进入 **Bridge → 基础配置 → 消息过滤**，选择 **白名单**，勾选允许回复的会话。
2. 在 **行为设置** 中开启 **独立窗口发送**。黑名单模式下此开关不可开启；开启后黑名单按钮不可选。
3. **手动把白名单中选择的每个会话打开为独立聊天窗口**，不能只是轮流在微信主窗口中查看。窗口可以最小化，但不要关闭。
4. 确保聊天输入框可输入，不要停留在搜索框、网页搜索或其他弹窗中，发送过程中避免同时操作微信。
5. 保存配置。Bridge 正在运行时，切换发送模式会先停止旧进程再启动新进程，旧进程未发送的消息不会迁移。

界面在开启后持续显示第 3 步提醒。白名单为空时不会发送任何消息，界面也会提示。

## 匹配与限制

- 以微信会话显示名称精确匹配 Win32 窗口标题和 UIA `Name`，验证微信进程与窗口状态，只接受唯一候选。
- 每次文字、图片、文件发送都会重新查找窗口，不保存长期 HWND 映射。
- 找不到窗口、标题不匹配、多个同名窗口、窗口关闭、进程变化或发送过程中失去前台焦点，都拒绝继续操作；不回退到 Ctrl+F，也不向当前其他窗口盲发。
- 粘贴与发送回车前分别复核目标。该检查不能消除 Windows 前台输入的全部竞争条件，也不能替代微信端实际验收。
- HWND 只是临时窗口标识，标题不是微信会话永久 ID。不同账号或会话存在相同名称时，请先改成可区分的名称；本模式无法仅靠标题证明账号/会话身份。
- 部分微信版本不暴露输入框控件。当前继续沿用剪贴板和键盘发送，未增加输入框焦点自动修复；请保持目标聊天输入框处于可输入状态。
- 会话改名后要等待消息路由刷新为新名称；窗口标题不匹配时会停止，不做模糊猜测。
- “以微信ID查找联系人”在此模式下禁用且不参与路由，关闭本模式后恢复其原设置。

## 白名单的范围

`group_reply_filter_sessions` 保存真实会话 ID，不是窗口句柄或显示名称。会话选择器同时展示群聊和私聊/其他会话，支持按名称或真实会话 ID 搜索。名称优先补全联系人备注或昵称，失败时仍显示真实 ID，避免私聊从列表消失；不会把最近一条消息摘要当作名称。也可在手动会话 ID 输入处补充暂未扫描到的会话。

启用本模式后，所有发送都要求目标会话在白名单内，包括群聊、私聊、普通机器人回复、本地指令和回溯附件回复。未知会话 ID 或空白名单都不会通过。发送队列在处理请求和后续消息片段前重新检查过滤设置。

## 配置字段

| 字段 | 默认值 | 约束 |
| --- | --- | --- |
| `uia_direct_window` | `false` | `true` 时必须使用白名单 |
| `group_reply_filter_mode` | `blacklist` | 本模式只允许 `whitelist` |
| `group_reply_filter_sessions` | `[]` | 允许回复的真实会话 ID；空列表不发送 |

Electron 在保存及启动时拒绝不合法组合。独立启动 Python 时，同样拒绝 `uia_direct_window=true` 配合非白名单配置；热更新也不能绕过限制。仅修改名单不会重启；切换发送模式需要重启。

## 验证

在 1.3.2 目录运行 `npm run test:bridge`、`npm run typecheck:bridge` 和 `npm run typecheck`。

自动化测试使用模拟窗口和模拟剪贴板，不向真实微信发送消息，覆盖多窗口精确匹配、重名/缺失拒绝、最小化恢复、焦点及标题变化、所有发送类型、配置白名单约束及切换重启。

关闭本模式后恢复 1.3.1 的搜索发送路径。此路径仍要求唯一可用的微信窗口；若有多个独立聊天窗口，需要先关闭多余窗口。
